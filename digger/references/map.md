# 地図の書式

元版の節順と、1資料1行の原文表を保つ。PDFと抽出テキストなど複数のファイルは同じ行へ並べる。節を周ごとに重複させず、各節の末尾へ追加する。

```markdown
# map: 話題

問い: 調べたいこと
最初の検索語: 最初に使った言葉

## 要る主張
- [ ] 確かめたい論点 — 状態、根拠のファイル・行、短い原文

## 用語
- 用語（別の呼び方）— 出たURLまたは保存ファイル

## 人
- 名前（所属）— 代表作と確認元

## 場
- 知見が集まる場所 — URL

## 原文（sources/）
| 論文・資料 | ファイル | 元のURL | どこから来たか（周・動き） |
|---|---|---|---|

## 次の手がかり
- 未探索のもの — たどる価値がありそうな理由
```

所属や公開状況を本文で確かめていない行には「未確認」を付ける。原文表には次の種類の印を1つ付け、信頼度の点数は付けない。

| 印 | 内容 |
|---|---|
| 〔論文〕 | 論文・プレプリント。査読の有無は別途分かるようにする |
| 〔本人〕 | 試した・作った・測った本人の記録 |
| 〔観察〕 | 他人の作品や方法を観察した記録 |
| 〔まとめ〕 | 他人の知見を集めた解説や一覧 |
| 〔公式〕 | 道具・製品を作った側の文書や発表 |

〔観察〕で対象の人物が分かるなら、その人自身の記録を次の手がかりにする。〔まとめ〕は引用先を探す入口にし、根拠には元の本人の記録や論文を優先する。

分かる場合は「作例あり」「測定あり」「AI補助」「宣伝あり」「未読」「自動字幕」「OCR」「音声認識」を添える。AI補助は本人の開示などで確認できた場合だけ付ける。作品の上手さや主張の優劣は採点せず、原典を読むユーザーに判断材料を渡す。
