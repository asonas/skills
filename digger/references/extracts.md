# 抜き書きの作成と照合

`extracts.json` は元版の `report.py` と同じ書式を使う。`file` は話題ディレクトリ内の `sources/` からの相対パス。原本を別ルートに保存しても、照合する抽出テキストは `sources/` 内に保持する。

## 読むための引用を選ぶ

`map.md` の短い引用を手がかりに、原典の段落・節を読み直して選ぶ。読む引用では、誰が何について述べたか、問いに必要な手順・理由・条件・例外が分かるまとまりを残す。「その問題」「この方法」の参照先が必要なら前の文を含める。見出しやリンク名だけの目印は資料案内へ置く。短くても意味が通る引用や、手順が揃った列挙はそのまま使える。

「人のやり方」を調べるときは、実務者ごとに手順と理由を読める節を作る。共通点・相違点の節では誰の条件かを保ち、別人の手順を一つの推奨手順に合成しない。作業順・信号順・説明順は原典で区別し、分からなければ未確認とする。論点の各部分と節の対応は `map.md` に記録する。

外国語の引用には `ja` に日本語訳を添える。訳は原文の範囲に対応させる。`note` / `context_note` は著者・資料・適用範囲の案内に使い、引用から落とした理由や条件は原文の引用へ戻す。HTMLの文脈展開を開かなくても、抜き書きの意味と重要な限定が読めるようにする。

粒度は [良い例と修正例](extract-examples.md) で確認する。

## データの形

```json
{
  "title": "調査の題名",
  "question": "調べた問い",
  "stopped": "終了条件と到達点",
  "claims": [
    {
      "claim": "確かめたい論点",
      "status": "一部だけ",
      "note": "どの範囲まで原典が付いたかの短い注記",
      "quotes": [
        {
          "file": "author-year-title.txt",
          "line": 10,
          "end": 11,
          "text": "原文からそのまま切り出した文",
          "ja": "原文が外国語の場合の日本語訳",
          "mark": "〔本人〕測定あり"
        }
      ]
    }
  ],
  "disagreements": [],
  "unreached": ["取れなかった資料と理由"]
}
```

`status` は「付いた／一部だけ／付かなかった」。構造上 `note`、`end`、`ja`、`mark` は省略可だが、外国語を引用するときは訳を付ける。食い違いは `disagreements` に `topic` と `quotes` を置き、引用には `who` を添える。条件が違う事例はまず分けて示し、同条件での食い違いは両方の原文を並べる。

行番号は改行文字で数える。PDFのページ区切りを追加の改行と数えない。動画は保存した字幕の行番号に加え、原文に含まれる時刻も残す。途中を省略する場合は `…` で区切る。自動字幕やOCRの誤変換は引用内で修正しない。

## 照合と生成

Python 3.10以上の解決先とバージョンを確認してから、スキル内の実際のパスで実行する。mise管理の環境での例：

```sh
mise exec -- python3 "$DIGGER_SKILL_DIR/scripts/report.py" "$TOPIC_DIR" --check
```

この例の変数は解決済みのスキルと話題ディレクトリに設定する。`--check` はファイルを生成せず、不一致なら終了コード1。全文・引用範囲・行番号を確認して直し、原文を引用に合わせて書き換えない。

照合は指定範囲の前後2行を含み、空白・箇条書きの印を正規化し、`…` の各断片が順に存在するかを見る。原文との一致を確認するもので、内容の正しさ・網羅性・OCRや翻訳の正確さを保証しない。

照合と、有効な場合のJev確認を終えた JSON から、次の2コマンドで `report.md` と `report.html` を標準で作る。各コマンドは生成時にも再照合し、不一致ならその形式の既存ページを保持する。

```sh
mise exec -- python3 "$DIGGER_SKILL_DIR/scripts/markdown.py" "$TOPIC_DIR"
mise exec -- python3 "$DIGGER_SKILL_DIR/scripts/report.py" "$TOPIC_DIR"
```

`text` は引用ブロックへそのまま、`ja` は「訳」、`note` は注記として分ける。論点ごとの状態、資料のメタデータへのリンク、本文へのリンク、行番号を付ける。メタデータは本文の拡張子を除いた名前に `-metadata.md` を付けて同じディレクトリへ保存する。原典URLはそこに記録する。生成物末尾の `digger:related:start` / `digger:related:end` 間だけは再生成時も保持する。Wikiリンクはその範囲に置く。

エージェントが加えるのは見出し・状態・短い注記・訳に限り、注記にも結論や評価を加えない。未解決点は `unreached` に残す。取得できた原典自体を生成したレポートで置き換えない。

HTML生成では `--check` を付けない。`--check` だけではHTMLは作られない。`report.html` は元版と同じ前後の文脈を開けるページで、`report.md` と同じ `extracts.json` を使う。両コマンドの成功と両ファイルの生成を確認し、HTMLとMarkdownのリンクを返す。片方が失敗したら既存ファイルの存在だけで成功と扱わず、未生成・未更新の形式を知らせる。ユーザーが形式を明示的に限定した場合だけ片方の生成でよい。

## 不足への対応と完了判定

文字列照合後、原典の裏付け、表示する引用の十分さ、同じ論点の引用を合わせた充足を確認する。有効な場合は [Jev](jev.md) が補佐する。注記や周辺本文だけに答えがある状態は、読む引用として未完成。

| 確認した不足 | 次の行動 |
|---|---|
| 原典にはあるが引用から落ちている | 必要な原文へ引用を広げるか追加し、訳・照合・Jev確認も更新 |
| 原典にも必要な説明がない | その部分だけ追加探索。上限等で止めるなら未確認を残す |
| 対象・条件・順序の種類が異なる | 人・適用条件ごとに分け、同じ手順や矛盾として扱わない |
| 音声・実演の確認が必要 | 該当位置を確認するか、未確認として残す |

「付いた」は引用全体で論点に答え、必要な限定も読める場合。「一部だけ」は有用な根拠があっても必要な部分が残る場合。「付かなかった」は回答の根拠がない場合。広い問いは必要な部分に分けて確認する。関連語や引用件数だけで完了を決めない。

引用の修正で済む場合は先に再抽出し、原典の不足が分かった場合に追加探索へ戻る。探索を停止した理由と、読める成果物としての完成状態は分けてログへ記す。飽和・回数・ユーザー上限で終了する場合は未充足を保持する。
