# Digger

問いを調べるための原典と、読むべき箇所を揃える。論文、実践者の記事、動画を対象とし、その分野で知識が集まる場所を調べてから探索する。原文を要約せずに保存し、止めどきは確信度ではなく証拠で決める。調査の早い段階で結論を固めず、ユーザーが原文を読んで判断できるようにする。

## 1. 保存先と環境を確認する

[設定の契約](references/configuration.md)を読み、利用設定とこのマシンの環境記録を開く。設定がなければ `setup-digger` を案内し、保存先を推測して作業を始めない。

環境記録がない、今回の設定と一致しない、または必要な機能が `ready` でなければ、セットアップでその機能を確認する。今回使う取得方法のコマンド解決先と実行可否も確認する。確認済みという過去の記録だけで利用可能と判断しない。不足があればセットアップで該当機能を修復するか、利用可能な資料だけで続けるかをユーザーに聞く。調査中に未選択の文字起こしサービスへ切り替えない。

Obsidian を選んだ場合は `obsidian-vault` の保存先解決と組織ルールを適用する。設定した Vault 内の保存先を明示指定として扱う。調査と保存の依頼、またはこのスキルの明示的な呼び出しの範囲で保存する。相談だけで起動した場合は保存の意向を確かめる。

話題を表す短い英小文字・ハイフンのディレクトリを保存先に作る。同名の調査があれば問いと原典一覧を読み、同じ調査なら続きを行い、異なる調査なら別名を選ぶ。再開時も原典と過去のログを保持する。

## 2. 問いと探索の入口を作る

Obsidian連携では、外部調査の前に [既存知識とWiki連携](references/wiki.md) に従ってWikiと出典を確認する。qmdが使えれば `vault-rag` のwiki-first手順を使う。既存資料のURL・DOI・版・取得範囲を照合し、使える原典は再利用する。検索順位だけで根拠が揃ったとは判断しない。

`jev.enabled: true` なら [Jev連携](references/jev.md) に従い、既存根拠を `knowledge.json` に整理して `scripts/jev.py gaps` を実行する。Obsidian以外の保存先でも使える。根拠不足・矛盾・更新の必要を区別し、実行者が原典と突き合わせて探索する論点を決める。未設定・無効・失敗時は通常の読解で続け、未確認と記録する。

既存資料だけで今回の問いに答えられ、追加探索や最新確認の依頼がなければ「既存資料で充足」として出典を案内して完了できる。それ以外は不足する論点を次の探索へ渡す。

`map.md` に問いと、答えるために原典を確認したい論点（元版の「要る主張」）を3〜6個書く。

- 最初の論点は「この分野の知見はどこに集まっているか」にする。
- 少なくとも1つは依頼の具体的な条件をそのまま含める。
- 半分以上は効果・限界・失敗例など、本文を読む必要がある形にする。
- コツや定番のやり方を調べる場合も、元になった原典・研究があるかを論点に含める。

異なる2つの入口から調べる。通常は日本語と英語、または用語検索と総説・入門資料。それぞれ用語（出たURL）、人物（所属・代表作）、場（知識が集まる場所）、定番の資料（題名・著者・年・公開URL）を返す。「見つけた／探したが無い／探していない」を分け、未探索のものを次の手がかりへ移す。名前とURLを拾い、この段階で要約はしない。

分野が分からない段階では、百科事典→専門事典→教科書・講義資料→総説→原著と進む。論文のない分野なら用語集・入門記事→名前の挙がる人物→その人自身の実践記録と進む。論文と実践者のどちらに知見があるか、見るべき場を固定の一覧から決めつけない。

検索の深さを選べる環境では通常の検索から始め、必要な資料の種類が見つからないときに深い検索へ切り替える。記事はあるが動画がない、英語はあるが日本語がない、といった種類ごとの不足を見る。

実行者自身が2つの探し方を順に行う。並行エージェントはユーザーが明示的に依頼した場合にだけ使い、同時に2本までとする。その場合は読み取り・検索だけを担当させ、ファイルの取得と保存は実行者が行う。各担当への依頼、返却・停止の状態もログに残す。

`map.md` は [地図の書式](references/map.md)に従い、節の順序を保って各節の末尾へ追記する。次の情報を保持する。

- 問いと論点ごとの状態：未探索／調査したが根拠なし／一部確認／確認済み。
- 用語、人物、情報の集まる場所と、それぞれを知った URL。
- 原典一覧：資料ID、題名、著者、公開日、URLまたはDOI、取得日時、保存先、取得範囲、抽出方法。
- 論点ごとの根拠位置と、まだ確かめられていない点。
- 次にたどる手がかり。

検索結果の抜粋だけで得た情報は未確認とする。検索語には公開してよい話題だけを使い、Vault の私的な文章をそのまま外部に送らない。

## 3. 原典を取り込み、そこからたどる

繰り返し引用される資料、総説、実践者自身の記録など、問いに関係する手がかりを選ぶ。[取得・変換手順](references/acquisition.md)に従って取得し、本文を確認できた資料だけを取得済みとして記録する。

原典から次の6つの動きでたどる。

| 動き | 論文 | 実践者の発信 |
|---|---|---|
| 後ろへ | 参考文献 | 記事内リンク、参考にした記事 |
| 前へ | 被引用文献 | 紹介・引用している記事や投稿 |
| 著者で追う | 同じ著者の論文 | ブログ、投稿一覧、チャンネル |
| 場を通しで見る | 学会・雑誌 | タグ、フォーラム、資料一覧 |
| 近くを眺める | 同じ号や一覧 | 関連記事、再生リスト |
| 言葉で引き直す | 増えた専門用語 | 俗称・略語も含めた検索 |

論文は DOI を優先し、題名で探した場合は題名・著者・年を照合する。引用索引の0件を「引用なし」と判断せず、本文の参考文献や引用している記事も探す。同名著者は所属や本人の資料一覧と照合する。複数の説明が考えられるときは、別々の手がかりとして確かめる。問いが変わったら `map.md` を更新し、変更理由を `log.md` に残す。

各論点に、資料IDとページ・節・行・時刻などの位置、照合用の短い原文を付ける。引用は保存した本文と照合する。OCRと音声認識の出力は機械抽出として明記し、結論を左右する数字・否定・固有名詞は原画像や音声で確認する。確認できなければ不確実な根拠として残す。

入口の探索を0周目とし、原典を保存してそこから少なくとも1回、後ろへ・前へ・著者で追う動きをするまでを1周とする。各周の検索語、たどった先、取得失敗と理由、次に進む判断を `log.md` に追記する。既存の記録は書き換えない。並行探索中なら全担当の返却を待って周の終わりを判断する。

## 4. 終了を判断する

ユーザー指定の時間・回数の上限を優先する。上限がなければ入口の探索後に最低1周進め、次のどれかで止める。

- 全論点に本文で確認した根拠位置が付き、残る限定条件も明記できた。
- この周で挙がった人物と資料の7割以上が既に `map.md` にあり、新しい用語もほとんど出ない。分母・分子をログに記録する。7割は元版の試行上の目安であり、網羅性の保証ではない。
- 4周に達した。
- 残る論点の根拠がログイン・有料の資料だけになった。著者や大学の公開版など、正規の別の入手先も確認してから判断する。一部確認の論点も、残りを無料で探せるなら続ける。無料ページがボット対策で取得できないだけなら、利用できるブラウザやユーザーによる閲覧で確認できるかを先に検討する。

飽和を数えるのは同じ問いを異なる方法で探した2つの結果だけ。別仮説どうしの結果は比較せず、仮説ごとの根拠で判断する。既知の一覧には実行者が直接拾ったものも含める。見つかった候補のうち保存して関連を確認できた資料が0件だった探索は空振りとし、その周は飽和の判断に使わない。

0周目で根拠が揃ったように見えても、ユーザーの上限や取得不能の場合を除き1周は行う。続ける場合は次にたどる手がかりを2〜4個選んでログに書く。ユーザー指定の上限で打ち切った場合は、それを他の終了条件と区別して記録する。

終了理由と論点ごとの到達点をログに記す。探索の飽和や回数上限を、事実が存在しない証明や調査の網羅性と扱わない。動かした取得処理が終了していることを確認する。

## 5. 読める形で渡す

話題ディレクトリには次を残す。

| ファイル | 内容 |
|---|---|
| `map.md` | 問い、探索地図、原典一覧、根拠の対応 |
| `log.md` | 追記式の探索経過、失敗、終了理由 |
| `sources/` | 取得した本文、字幕、機械抽出テキスト、原典ごとのメタデータ |
| `extracts.json` | 原文と照合するための抜き書きデータ |
| `report.md` | 照合済みデータから作る、論点別の抜き書きと原典へのリンク・位置 |
| `report.html` | 同じ抜き書きをブラウザで読み、引用の前後の文脈を展開できるページ |

[抜き書きの作成・照合](references/extracts.md)に従って `extracts.json` を作り、同梱の元版 `scripts/report.py --check` で照合する。1件でも不一致なら、出典位置と原文を確かめ直し、通るまで新しい抜き書きページを作らない。標準で `report.md` と `report.html` の両方を生成する。ユーザーが出力形式を明示的に限定した場合のみ、その指定に従う。

Jevが有効なら照合後、レポート生成前に [Jev連携](references/jev.md) の `scripts/jev.py citations` を実行する。条件の省略・否定・矛盾の指摘は周辺の原文で確認し、引用または説明を直す。結果ファイルへのリンクと採否を `log.md` に残す。Jevの値だけで探索を終了せず、失敗を確認済みと扱わない。

抜き書きは引用ブロックにし、説明・翻訳・推論はブロックの外で区別する。自動字幕と音声認識は、著者が校閲した原文と区別する。本文を取り込めなかった資料は URL と未取得の理由を残し、抜粋から全文を補完しない。

同じ Vault 内のノートには Vault 相対のリンクを使う。同名の `map.md` などを取り違えないようパスを省略しない。Vault 外の原本は解決可能なリンクと元 URL を記録する。原文本文には Wiki リンクを挿入せず、関連ノートへのリンクはメタデータか生成した説明に置く。

生成コマンドが成功し、今回の `extracts.json` から `report.md` と `report.html` の両方が生成されたことを確認してから完了とする。片方が失敗した場合は部分完了として知らせる。読む入口として `report.html`、保存・Wiki連携用として `report.md` のリンクを示し、優先して読む資料を2〜4本、読む箇所とともに返す。終了理由、論点ごとの根拠位置、届かなかった資料とその重要性、取得や探索の問題を短く伝える。標準出力は原典と抜き書きであり、要約・解説は依頼された場合に別ファイルへ作る。

最後に「感覚と合った？」と聞き、回答があれば `log.md` に原文のまま追記する。返事を待って調査処理を動かし続けない。飽和の割合や周の上限を変える提案は、この記録を複数回分見て判断する。

Wikiへの反映は [既存知識とWiki連携](references/wiki.md) と設定の `wiki.mode` に従う。`after-research` の入力は今回の `report.md` に絞るが、根拠確認では原典まで読む。継続調査の依頼では [取得補助と新着確認](references/helpers.md) の `watch.py` を使える。定期実行は別途依頼された場合のみ設定する。
