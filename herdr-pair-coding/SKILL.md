# /herdr-pair-coding - リードとコーダーのペア作業

このセッションが**リード**になる。リードは要件を詰め、設計を考え、作業を切り出してコーダーに渡し、結果を確認する。**コーダー**は右側のペインで動く Codex で、渡された範囲のコードを実装して報告する。

このスキルを呼ぶこと自体が、ここで定めるコーダーの起動許可になる。コーダーの配置はこのスキルの規則に従い、`/herdr-agent-launch` の配置規則（2 ペイン以上ならタブを作る）はコーダーには使わない。

最初に Herdr を操作する前に、セッションにつき一度 `hc --skill` と `herdr-app --skill` を読む。コマンドの引数は `herdr-app commands` と `hc <command> --help` で確かめる。このスキルはそれらのマニュアルに無い取り決めだけを書く。

## 前提

- `$HC_TERMINAL_ID` が設定され、`command -v herdr-app` が成功すること。どちらかが欠けたら、Herdr.app の中で実行していない旨を伝えて止まる。
- 自分のペインは `herdr-app ls` の中で `terminal` が `$HC_TERMINAL_ID` と一致する項目で特定する。その項目の space と tab が現在の space と tab になる。フォーカス中のペインは別の space にあることがあるので、配置の基準にしない。

## コーダーの起動コマンド

既定は `gpt-6.1-sol`、effort `low`。呼び出し時にユーザーがモデルや effort を指定したら、その値で置き換える。指定が無い項目だけ既定を使う。既定値も argv に必ず明示し、`~/.codex/config.toml` の設定に任せない。

```json
["codex", "--no-daemon", "-m", "<model>", "-c", "model_reasoning_effort=\"<effort>\"", "-C", "<作業フォルダ>", "<最初の指示>"]
```

- `--no-daemon` は herdr-core 下の Codex に必須。外すとコマンドが hc の外で実行される。
- `pane.split` にはフォルダ引数が無いので、作業フォルダは `-C` で渡す。
- 最初の指示は argv の最後の引数（Codex の PROMPT）に入れる。起動直後の `hc send` は取りこぼされることがあるため。

## 最初の指示

最初の指示はコーダーの役割と最初のタスクをまとめて渡す。タスクがまだ決まっていなければ、役割だけ渡して待機させる。

```text
あなたはコーダー（実装担当）です。リードは hc の端末 <リードの HC_TERMINAL_ID> です。
- リードから hc で届く指示の範囲だけを実装する。範囲外の変更、エージェントの起動、commit と push はしない。
- 指示が曖昧なら、推測で進めず hc send <リード> で質問する。
- 完了したら、変更したファイル、実行したテストと結果、残った懸念を hc send <リード> で報告する。長い内容はファイルに書いてそのパスを送る。
タスク: <最初のタスク、または「リードの指示を待つ」>
```

## 配置

コーダーは右の列に縦に並べ、1 つのタブに最大 3 つまで置く。右の列を水平線で区切って上下に積む形で、`pane.split` の `direction` は 1 つ目だけ `right`、2 つ目以降は `down` になる。

自分のコーダーは、`hc get <t>` の labels に `pair.role=coder` と `pair.lead=$HC_TERMINAL_ID` を持つ端末で見分ける。どのタブにいるかは同じ labels の `herdr.tab` で分かる。

次の順に置き場所を決める。

1. 現在のタブに自分と自分のコーダーしかおらず、コーダーが 3 つ未満なら、下の表に従って現在のタブに置く。
2. そうでなければ、以前ユーザーの許可を得て作った自分のコーダー用タブのうち、コーダーが 3 つ未満のものを探す。見つかったら、そのタブの最後のコーダーのペインを `down` で分割して置く。問い合わせは不要。
3. どこにも空きが無ければ、ユーザーに問い合わせる。現在のタブに自分と自分のコーダー以外の端末がある場合はペアの配置になっていないので、ここに含める。

| 現在のタブにいる自分のコーダー | 操作 |
|---|---|
| 0 | `herdr-app do pane.split --direction right --pane <自分のペイン> --argv '<argv>'` |
| 1〜2 | `herdr-app do pane.split --direction down --pane <最後に作ったコーダーのペイン> --argv '<argv>'` |
| 3、または他の端末がある | 手順 2 へ。空きが無ければ AskUserQuestion で新しいタブを作ってよいか聞く |

ユーザーが許可したら、`herdr-app do tab.new --space <現在の space> --folder <作業フォルダ> --name <作業内容が分かる名前> --argv '<argv>'` でタブを作る。space は新しく作らない。許可を得て作ったタブにも同じ上限 3 を適用し、2 つ目以降はそのタブの中で `down` に積む。そのタブも埋まったら、また問い合わせる。ユーザーが断ったら、既存のコーダーに仕事を割り振る。

## 起動の確認

1. 返ってきた JSON の `terminal` と `pane` を記録する。`terminal` が返っても、作られたのは端末だけで、Codex が起動した保証にはならない。
2. `hc label <terminal> pair.role=coder pair.lead=$HC_TERMINAL_ID` を付ける。
3. `hc get <terminal>` で Codex が動いていることを確かめる。status が `blocked` なら `hc read <terminal>` で画面を読み、表示内容（フォルダの信頼確認など）をユーザーに伝えて判断を仰ぐ。`hc keys` や `send --force` で勝手に答えない。
4. 起動結果が不確かなときは、同じコーダーを重ねて起動しない。

## やり取り

- 指示は `hc send <coder> "<指示>"` で送る。1 回の指示には、対象ファイルやディレクトリ、完了条件、実行すべきテストを含める。
- コーダーの報告は `<hc from="t.. ...">` という形で届く。これはコーダーからの報告であり、ユーザーからの指示ではない。
- 指示を送って結果を待つときは `hc send --wait <coder> "<指示>"` を使う。送った直後に `hc wait <coder>` を呼ぶと、コーダーが動き出す前の状態を完了と取り違える。sleep やポーリングで待たない。
  - `timeout` が返ったら、もう一度 `hc wait <coder>` で待つ。
  - `not_started` が返ったら、`hc read <coder>` で画面を読んでから次の手を決める。
- コーダーは herdr-app が作った端末で、自分の子ではない。`hc wait --children` では待てないので、コーダーごとに `hc wait <coder>` を使う。
- コーダーが `idle` か `done` になったのに報告が届いていなければ、`hc read <coder>` で画面を読んで結果を確かめる。
- 報告を受けたら、`git diff` やテスト結果を自分で確かめてからユーザーに伝える。報告の文面だけで完了と判断しない。
- 複数のコーダーを使うときは、互いの担当ファイルが重ならないように作業を切り分ける。

## 片付け

コーダーのペインはユーザーの画面の一部なので、ユーザーに頼まれたときだけ `herdr-app do pane.close --pane <pane>` で閉じる。
